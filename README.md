# Pro.Max Cabinet Studio

نرم‌افزار دسکتاپ فارسی برای ثبت یونیت‌های کابینت، بازسازی ابعاد برش از فایل اکسل و تهیه‌ی لیست قطعات. رابط کاربری راست‌به‌چپ است و داده‌ها به‌صورت محلی روی همان دستگاه نگهداری می‌شوند.

## تحلیل فایل Google Drive

بررسی روی جدیدترین نسخه‌ی دقیقاً هم‌نامِ `analiz pro.2.xlsx` انجام شد (فایل‌های هم‌نام دیگری هم در Drive وجود داشتند). فایل ۵ شیت دارد:

- `کابینت زمینی` و `آنالیز زمینی`: ۱۱ یونیت زمینی، اندازه‌ها، تعداد قطعات، نوار لبه و پشت‌بند ۳ میل.
- `کابینت هوایی` و `آنالیز هوایی`: ۲۰ یونیت هوایی، قطعات بدنه، کف، تاق، طبقه، قید، درب و پشت‌بند.
- `کشو`: ورودی تعداد، عمق، عرض و ارتفاع و فرمول بدنه، جلوی کشو و پشت کشو.

نمونه‌ی آغازین برنامه با همین ۱۱ یونیت زمینی، ۲۰ یونیت هوایی و ورودی کشو ساخته شده است؛ از دکمه‌ی «ورود از Excel» هم می‌توان نسخه‌ی دیگری از فایل را وارد کرد. در واردکردن، مقادیر، ابعاد و تعدادهای اصلی خوانده می‌شوند و فرمول‌ها در خود برنامه محاسبه می‌شوند.

### قواعدی که در نسخه‌ی اول پیاده‌سازی شده‌اند

- عرض درب براساس بازه‌های فایل: ۱۰ تا ۵۰ → یک درب، بیش از ۵۰ تا ۱۰۰ → دو درب، بیش از ۱۰۰ تا ۱۵۰ → سه درب؛ عرض هر درب = عرض یونیت ÷ تعداد درب − ۰٫۲.
- زمینی: عرض داخلی و طول طبقه/قید = عرض − ۳٫۲؛ پشت‌بند ۳ میل = (عرض − ۱٫۶) × (ارتفاع + ۰٫۸).
- هوایی: عرض داخلی = عرض − ۳٫۲؛ عمق تاق = عمق − ۲؛ عمق طبقه = عمق − ۳؛ پشت‌بند ۳ میل = (عرض − ۱٫۶) × (ارتفاع − ۰٫۸).
- کشو: طول بدنه = عمق − ۵؛ عرض بدنه = ارتفاع ÷ ۳ − ۴؛ طول جلوی کشو = عرض مجموعه − ۹٫۱؛ پشت کشو ۲ سانتی‌متر باریک‌تر از جلو.
- نوار لبه براساس پرچم‌های نوار در فایل محاسبه می‌شود. مساحت قطعه‌ها جمع می‌شود و تعداد ورق خام با بهینه‌سازی برش (صفحه‌ی لیست برش) محاسبه می‌شود.

**نکته‌ی مهم:** فایل اصلی واحد اندازه‌گیری را صریح تعیین نمی‌کند؛ برنامه با توجه به مقادیر، سانتی‌متر را فرض می‌کند. پیش از برش، واحد، ابعاد درب‌ها و همه‌ی اندازه‌ها را با نقشه‌ی نهایی و روش کارگاه تطبیق دهید.

## امکانات فعلی

- افزودن، ویرایش، کپی و حذف یونیت زمینی، هوایی و مجموعه‌ی کشو.
- محاسبه‌ی زنده‌ی قطعات برش، تعداد درب خودکار، متراژ نوار لبه و مساحت مواد.
- جست‌وجو و فیلتر در فهرست یونیت‌ها و لیست برش.
- ورود داده از فایل `.xlsx` (حداکثر ۲۵ مگابایت؛ پس از تأیید جایگزین پروژه‌ی جاری می‌شود) و خروجی Excel چندشیتی (لیست برش، خلاصه‌ی متریال، یونیت‌ها و روش محاسبه) به‌همراه شیت پشتیبان پنهان برای بازگردانی دقیق پروژه.
- ورود Excel در برابر ارجاع‌های خراب، یونیت‌های غیرفعال و شیت کشوی خالی مقاوم است و هشدارهای فارسی را به‌صورت بنر زرد RTL نمایش می‌دهد.
- چیدمان بهینه‌ی برش روی ورق (الگوریتم گیوتین) با ابعاد ورق و ضخامت تیغ قابل تنظیم، درصد پرت و نقشه‌ی SVG هر ورق.
- برآورد هزینه و پیش‌فاکتور: قیمت ورق (عمومی و اختصاصی هر متریال)، نوار لبه، دستمزد/CNC و یراق‌آلات؛ ذخیره‌ی محلی قیمت‌ها و چاپ/PDF پیش‌فاکتور همراه لیست برش.
- چاپ یا ذخیره‌ی PDF از پنجره‌ی چاپ؛ خروجی پشتیبان JSON.
- ذخیره‌ی خودکار پروژه در حافظه‌ی محلی مرورگر/برنامه‌ی دسکتاپ؛ بدون ارسال داده به سرور.
- بسته‌بندی دسکتاپ با Electron برای Windows.

## اجرا

نیازمندی: Node.js نسخه‌ی ۲۰٫۱۹ به بالا یا ۲۲٫۱۲ به بالا.

```bash
npm install
npm run dev
```

آزمون‌ها و اعتبارسنجی‌های پروژه:

```bash
npm test
```

برای اجرای پوسته‌ی دسکتاپ در زمان توسعه:

```bash
npm run desktop:dev
```

برای ساخت نصب‌کننده‌ی Windows x64 روی دستگاه Windows:

```bash
npm ci
npm run dist:win
```

خروجی نصب‌کننده در پوشه‌ی `release/` ساخته می‌شود
(`Pro.Max-Cabinet-Studio-<version>-Setup.exe`) و در Git ثبت نمی‌شود.

### ساخت خودکار نصب‌کننده با GitHub Actions

گردش‌کار [`.github/workflows/build-win.yml`](.github/workflows/build-win.yml) روی `windows-latest` با Node 20 اجرا می‌شود و:

1. `npm ci` و `npm test` را اجرا می‌کند.
2. `npm run dist:win` را می‌سازد.
3. نصب‌کننده‌ی `release/*.exe` را به `dist/` کپی می‌کند و `dist/*.exe` را با `actions/upload-artifact@v4` به‌عنوان آرتیفکت `promax-cabinet-studio-windows-x64` آپلود می‌کند.
4. در صورت اجرا روی تگ `v*` (یا تعیین `release_tag` در اجرای دستی)، فایل نصب را به GitHub Release ضمیمه می‌کند.

راه‌اندازی:

```bash
git tag v0.1.0
git push origin v0.1.0
```

اجرای دستی از تب Actions (workflow_dispatch) هم ممکن است؛ اگر ref انتخاب‌شده تگ `v*` نباشد، فقط آرتیفکت ساخته می‌شود، مگر آنکه در ورودی `release_tag` نام یک تگ موجود وارد شود.

بسته بدون امضای دیجیتال ساخته می‌شود (`CSC_IDENTITY_AUTO_DISCOVERY=false`)، پس ویندوز ممکن است هشدار SmartScreen نشان دهد. برای رفع آن باید گواهی Code Signing در Secrets مخزن تعریف شود.

### امنیت

`electron/main.cjs` با `contextIsolation: true`، `nodeIntegration: false`، `sandbox: true`، `webviewTag: false` و `devTools` فقط در حالت توسعه اجرا می‌شود. هیچ IPC، preload یا `contextBridge`ی وجود ندارد؛ رندرر کاملاً محلی است و به فایل‌های سیستم دسترسی ندارد. تمام درخواست‌های permission رد می‌شوند؛ ناوبری و redirect بیرونی با allowlist پروتکل `http/https` به مرورگر سیستم سپرده می‌شود و در توسعه فقط origin دقیق Vite مجاز است. CSP در خروجی build به `dist/index.html` تزریق می‌شود.

گزارش کامل: [`docs/security-review-electron.md`](docs/security-review-electron.md)

## بهینه‌سازی برش (چیدمان ورق)

صفحه‌ی **لیست برش** یک پنل «محاسبه‌ی بهینه‌سازی برش» دارد. با تعیین ابعاد ورق (پیش‌فرض ۱۸۳۰ × ۳۶۶۰ میلی‌متر)، ضخامت تیغ اره (پیش‌فرض ۴ میلی‌متر) و اجازه‌ی چرخش ۹۰ درجه، قطعات هر متریال جداگانه روی ورق چیده می‌شوند.

- الگوریتم: **Guillotine** با هیوریستیک **Best Short Side Fit**؛ هر چیدمان از برش‌های سرتاسری ساخته می‌شود، پس روی اره‌ی ورق‌بر قابل اجراست.
- ضخامت تیغ بین قطعات مجاور و کنار پرت رزرو می‌شود؛ قطعه‌ها هرگز هم‌پوشانی ندارند.
- قطعه‌ی بزرگ‌تر از ورق (در هر دو جهت) کنار گذاشته می‌شود و پیام فارسی آن در نتایج و زیر هر متریال نمایش داده می‌شود؛ بقیه‌ی قطعات چیده می‌شوند.
- خروجی: تعداد ورق، درصد پرت (شامل تیغ اره)، مساحت پرت و نقشه‌ی **SVG** هر ورق با نام و ابعاد قطعه. نقشه در چاپ/PDF هم می‌آید.

کد الگوریتم در [`src/lib/optimizer.ts`](src/lib/optimizer.ts) (TypeScript strict) و کامپوننت نقشه در [`src/components/CutMap.tsx`](src/components/CutMap.tsx) است. آزمون‌ها شامل عدم هم‌پوشانی، رعایت تیغ، رد کردن قطعه‌ی بزرگ، تراز مساحت‌ها و **قابل‌برش بودن گیوتینی** هر ورق است.

```ts
import { optimizeCutListByMaterial } from './src/lib/optimizer';

const report = optimizeCutListByMaterial(cutList /* سانتی‌متر */, {
  sheet: { width: 1830, height: 3660 },
  kerf: 4,
  allowRotation: true
});

report.totals.sheets;          // تعداد ورق
report.totals.wastePercentage; // درصد پرت
report.groups[0].result.sheets[0].pieces[0].x; // مختصات میلی‌متر
```

## قیمت‌گذاری و پیش‌فاکتور

بعد از اجرای «محاسبه‌ی بهینه‌سازی برش»، کارت **برآورد هزینه** زیر نقشه‌های ورق نمایش داده می‌شود. قیمت‌ها از دکمه‌ی «تنظیمات قیمت» (نوار بالا یا منوی کنار) قابل ویرایش‌اند و در `localStorage` همان دستگاه با کلید `promax-cabinet-studio-prices-v1` ذخیره می‌شوند:

- **هزینه تخته MDF:** تعداد ورق هر متریال × قیمت همان متریال؛ اگر قیمت اختصاصی خالی بماند، قیمت مشترک هر ورق اعمال می‌شود.
- **هزینه نوار لبه:** متراژ لبه‌ی قطعات چیده‌شده × قیمت هر متر. اگر لیست برش طول لبه‌ی هر قطعه را داشته باشد (`edgeTapePerPieceCm`) همان استفاده می‌شود؛ در غیر این صورت محیط کامل قطعات به‌عنوان برآورد محافظه‌کارانه گرفته می‌شود.
- **دستمزد / CNC:** مبلغ ثابت، به ازای هر ورق یا به ازای هر قطعه.
- **یراق‌آلات:** مبلغ دستی کل فاکتور (لولا، ریل، دستگیره و…).
- **جمع کل** و **قیمت هر یونیت** (وقتی تعداد یونیت‌های پروژه مشخص است).

هر ردیف پول یک‌بار و با گرد کردن نیم‌به‌بالا به واحد تومان گرد می‌شود و جمع کل دقیقاً برابر مجموع ردیف‌ها است؛ بنابراین اختلاف شناور در فاکتور دیده نمی‌شود. دکمه‌ی «چاپ پیش‌فاکتور» یک برگ A4 تمیز شامل خلاصه‌ی هزینه، لیست کامل برش، جدول ورق‌های مصرفی و جای امضا می‌سازد (ذخیره به‌صورت PDF از همان پنجره‌ی چاپ).

منطق خالص در [`src/lib/pricing.ts`](src/lib/pricing.ts) و ذخیره‌سازی در [`src/lib/pricingStorage.ts`](src/lib/pricingStorage.ts) است؛ رابط‌ها در `src/components/PriceSettingsDialog.tsx`، `src/components/CostBreakdown.tsx` و `src/components/InvoiceSheet.tsx` قرار دارند.

```ts
import { calculateCost, costBatchesFromReport } from './src/lib/pricing';

const batches = costBatchesFromReport(optimizationReport, cutList);
const estimate = calculateCost({
  batches,
  settings: { sheetPrice: 2_500_000, edgeBandPricePerMeter: 30_000, laborRate: 500_000 },
  unitCount: 31
});

estimate.total;        // جمع کل (عدد صحیح)
estimate.pricePerUnit; // قیمت هر یونیت
estimate.lines;        // ردیف‌های شرح/مقدار/قیمت واحد/مبلغ
```

## محدودیت‌ها و پیشنهاد نسخه‌ی بعد

نسخه‌ی فعلی برای تولید قطعه و کنترل ابعاد اولیه است، نه تأیید نهایی برش. جهت رگه، رزرو لبه‌ی خام ورق، کف کشو، مالیات، سوراخ‌کاری و خروجی CNC هنوز محاسبه نمی‌شوند؛ برآورد هزینه هم فقط بر اساس قیمت‌های دستی همین برنامه است و با موجودی واقعی کارگاه تطبیق نشده است. ابعاد ورق، ضخامت تیغ و قیمت‌ها بین نشست‌ها ذخیره می‌شوند، اما تنظیمات ورق هنوز داخل فایل پروژه نیست.

پیشنهادهای ارزشمند برای توسعه:

1. ~~چیدمان بهینه‌ی برش~~ — انجام شد؛ گام بعدی: ذخیره‌ی تنظیمات ورق در پروژه و خروجی CSV/DXF چیدمان.
2. ~~قیمت‌گذاری و پیش‌فاکتور~~ — انجام شد؛ گام بعدی: مالیات/تخفیف، بانک یراق‌آلات به‌ازای هر قطعه و چند پیش‌فاکتور برای یک پروژه.
3. **طراحی دوبعدی/سه‌بعدی آشپزخانه** با دیوارها، لوازم و جای‌گذاری یونیت‌ها.
4. **خروجی کارگاهی/CNC** شامل DXF/CSV، برچسب و بارکد قطعات.
5. **مدیریت مشتری و سفارش**، نسخه‌بندی طرح، وضعیت اندازه‌گیری/ساخت/نصب و آرشیو.
6. **فرمول‌های قابل تنظیم** برای لقی، ضخامت‌ها، درب، پشت‌بند و پروفایل هر کارگاه.
